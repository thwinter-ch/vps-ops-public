## Security News

### Viral Security Hardening Thread (2.3M views)
A thread on X documenting OpenClaw security best practices went viral. Key recommendations:

1. SSH key-only authentication, disable root login
2. Default-deny firewall (ufw)
3. Fail2ban for brute force protection
4. Tailscale for private mesh networking
5. Expose SSH/web only via Tailscale
6. Node.js 22+ (latest security patches)
7. Owner-only bot access
8. Sandbox mode for risky operations
9. Command allowlists (prevent arbitrary execution)
10. Scoped API tokens (minimum permissions)

### Prompt Injection Incident Report
Community reports of an OpenClaw instance having **all emails deleted** via prompt injection from a malicious email. This highlights the importance of:
- Using models with strong instruction-following (Claude Opus 4.5 recommended)
- Sandboxing email access
- Treating all external content as untrusted data

### Malicious Skills in ClawHub
Security research by Koi identified **341 malicious skills** in the ClawHub ecosystem. Operators should:
- Audit installed skills
- Verify skill sources and reputation
- Be cautious with new skill installations
- Source: https://www.koi.ai/blog/clawhavoc-341-malicious-clawedbot-skills-found-by-the-bot-they-were-targeting

## Recommendations

1. **Verify OpenClaw version** — Run `openclaw --version` and ensure you're on 2026.1.29+
2. **Run security audit** — `openclaw doctor` and `openclaw security audit --deep`
3. **Review skill installations** — Check what's installed and remove untrusted skills
4. **Harden server** — Follow the 10-point checklist above if not already implemented
5. **Model selection** — Consider Opus 4.5 for improved prompt injection resistance
