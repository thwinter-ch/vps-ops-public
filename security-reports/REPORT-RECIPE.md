# Daily Security Report Recipe

## Purpose

Public Security Advisories (PSAs) documenting newly discovered vulnerabilities, threats, and mitigations relevant to AI assistant infrastructure (OpenClaw, VPS hosting, related tooling).

**This is NOT an analysis of our specific infrastructure.** These reports document what's new in the security landscape as a community service.

## Report Format

### Filename
`YYYY-MM-DD-security-report.md`

### Template

```markdown
# Security Report — YYYY-MM-DD

> **Disclaimer:** This report documents publicly known vulnerabilities and security news relevant to AI assistant infrastructure. It is provided as a community service and does not describe the security posture of any specific system. Always verify applicability to your own setup.

## Summary

Brief overview of what was found today.

## New Vulnerabilities

### [CVE-YYYY-XXXXX] — Short Description
- **Severity:** Critical / High / Medium / Low
- **Affected:** Software name and versions
- **Description:** What it does
- **Mitigation:** How to fix it
- **Source:** Link to advisory

(Repeat for each CVE)

## Security News

Notable security-related news, blog posts, or incidents relevant to the community.

## Recommendations

General recommendations based on today's findings.

---

*Report generated by Hugo 🦛 as part of daily security monitoring.*
*Source: [vps-ops-public](https://github.com/thwinter-ch/vps-ops-public)*
```

## Data Sources

Daily scan should check:
1. **OpenClaw/ClawdBot** — GitHub releases, security advisories
2. **Node.js** — Security releases
3. **Ubuntu/Debian** — USN (Ubuntu Security Notices)
4. **cloudflared** — Cloudflare Tunnel daemon CVEs
5. **Tailscale** — Security advisories
6. **Docker** — Container vulnerabilities
7. **General AI security** — Prompt injection research, agent security news

## Process

1. Cron triggers daily security scan (early morning UTC)
2. Hugo checks sources for new CVEs/advisories since last report
3. Hugo writes report to `security-reports/YYYY-MM-DD-security-report.md`
4. Hugo commits and pushes to `vps-ops-public`
5. If critical findings, Hugo alerts Thomas immediately

## What NOT to Include

- Specific details about our infrastructure
- IP addresses, hostnames, or configurations
- Internal security audit results
- Anything that could be used to target our systems

## Tone

- Factual, concise
- Helpful to other OpenClaw/VPS operators
- Links to official sources
- Clear mitigations when available
